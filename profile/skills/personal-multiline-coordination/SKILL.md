# Personal Multiline Coordination

Root assigns complete tasks and shared resources; task coordinators complete
their tasks independently. Optimize useful work and decision latency. Do not
turn messages, documentation, checks, locks, or commits into an approval system.

## Authority And Current State

Use the user's current or standing authority; this skill grants none. Read
referenced chats before relying on them. Task-level authority continues through
ordinary repairs and stages. Preserve scientific scope, explicit spending and
external-action boundaries; block only a missing decision's dependency path.

Keep one current owner for each fact: allocation ledger for resource ownership
and conditional successors, task state for effective authority/progress/pending
requirements, actual automation configuration for schedules, and journal for
important history. Link rather than maintain synchronized progress summaries.
Use current entry points at startup/resumption; historical handoffs and revoked
limits are not recurring instructions. Generic workflow belongs here, project
permissions and concrete execution interfaces in project instructions.

## Roles And Dispatch

Root owns global priority, complete-task assignment, shared-resource decisions,
cross-task conflicts, and authorized chat creation/archival. It does not
automatically perform document/Git integration, engineering repair, or repeated
stage acceptance. Give that work a concrete task owner or bounded worker.
Task owners handle plans, assigned resources, execution, diagnosis, repairs,
continuation, checks, evidence, documents, authorized commits, wakeups, and closure.
Discussion handles scientific analysis and experiment/analysis design, not
operational scheduling. It may submit a formed authorized experiment request.

Create persistent chats only under user authority for complete independent
tasks. Keep related phases, repairs, and container replacements in the same task.
Dispatch a compact goal, frozen acceptance, write surface, assigned resources,
and current-state entry point; do not paste the rule-change history.

For resources, reuse valid acceptance and check only authority, ownership
conflicts, and necessary live facts. Update the single ledger and promptly
notify the task owner. Logs, labels, replicas, and commits follow in batches.
The owner checks its own launch conditions, records adoption, and proceeds;
adoption/launch does not need a chat acknowledgment or another root review.

Size allocations to actual ready parallel work, not fixed task quotas.
Extra capacity can serve generation shards, collection, independent branches,
and evaluation without changing frozen scientific/training configurations.
Distinguish effective ownership, current use, and conditional future allocation
in the same ledger. Return capacity at safe boundaries during substantial
CPU-only work or dependency waits; short loading gaps do not require churn.
An executor retaining a node across such phases needs a natural-boundary version
change before another task can use it. Preserve protection until a receiving
owner takes responsibility. ETA is a forecast, not an invented cap or retry quota.

## Messages And Bounded Intake

Message only when a recipient must act: assignment/scope change, resource
request/return, a concrete dependency/risk, a cross-task decision, an ETA change
affecting another commitment, or complete delivery. Give the change, requested
action, and evidence pointer; batch related matters. Direct an authorized
interface risk to the actual dependent owner; involve root when resources,
priority, or responsibility need a decision. Do not route every fact via root.
"No reply needed" does not justify routine adoption/milestone/commit messages.

Handle urgent resource risks, corrections preventing current wrong action,
and genuine cross-task blockers immediately on the affected path. Save ordinary
requirements with source, unfinished action, and continuation point in existing
task state, then batch them. Close the current batch without absorbing every
arrival. Persist latest effective authority at intake, refresh pending work
before handoff/foreseeable compaction, and reread after resumption.
Send discussion only necessary scientific questions/results/protocol evidence,
not operational schedules or progress chasing.

## Writes, Commits, And Workers

Authorized owners directly edit their task/card/TODO entries and sourced journal
events. Exclusive files need no generic lock. Real shared-file concurrent writes
need the project's short exclusion around reread, precise patch, atomic save,
and readback. Never hold it across computation or remote waits; on contention
preserve the pending change and do independent work. Separate SSH endpoints may
share one filesystem. Preserve others' increments.

Authorized commits use one project-defined transaction mechanism spanning index
checks, explicit-path staging, and commit. Git's individual index locks alone
do not establish ownership of that transaction. Busy/staged work defers Git,
not execution; do not steal locks, reset/stash others' work, or negotiate each
turn in chat. Commit authority does not imply push authority.

Actively delegate useful container-local investigation, candidate implementation,
and independent checks to existing agent CLIs; do not stop at permission or a
demo. Run independent read-only or exclusive-write work in parallel when useful.
Use the configured fast default and explicitly select a user-authorized stronger
model for complex work or demonstrated gaps without an approval round.
Follow personal-subagent-boundaries: minimal context, exclusive writes, bounded
deliverable. Accept actual edits/results and proportionate checks without doing
the whole task again or mandating a second reviewer/report. Native structured
output may suffice. Note material elapsed time/rework in existing task evidence
when useful; do not create a reporting pipeline. Keep monitoring sessions separate.
Mechanical probes and simple resource decisions remain direct operations.

## Waiting, Succession, And Closure

Pause the owner's App heartbeat during active work. Arm only a useful future
decision not covered by reliable completion/failure events; reschedule on
meaningful changes and disable when no action remains. Saving recoverable state
and confirming background ownership is enough to wait; a Git batch is not a
prerequisite. Container monitoring/protection and authorized deterministic
continuation remain independently owned. Root follows global decisions only.

For explicitly requested succession, first preserve work and stop the old
coordinator's active dispatch and obsolete App wakeups, while keeping authorized
jobs/monitors/continuations running. Name a transition owner. A successor checks
actual execution and pending responsibilities before becoming the sole owner;
do not restart healthy jobs or mark the underlying task complete.
If the user requests testing root-led creation, root creates the task chats;
verify real dispatch, autonomous adoption, correct state/resource ownership,
and appropriate follow-up before archival. Do not test by repeating scientific
work or requiring routine acknowledgment messages.

Normally the task owner verifies original acceptance, saves readable results
and residual owners, hands off resources, stops obsolete wakeups, and delivers
once. Root decides follow-on resources/tasks and authorized archival, not another
stage review. Archive an ended source only after its work is complete or an
explicit successor actually owns all residuals. Archival stops no process and
deletes no evidence. Report only observed execution and Git/chat state.
Read references/source-notes.md only for provenance maintenance.
