# 维护时的场景验收

只在安装、修改或检验本设计时读取。不是普通任务每次必跑的检查表；静态校验不等于模型行为或真实平台验收。

| 实际请求/场景 | 可观察结果 |
|---|---|
| 一人要求先讨论研究想法 | 只读分析，不创建卡、启动实验或搭完整目录 |
| 复用现有环境完成一项短核算 | 直接交付；属于已有实验就归原卡，不强制新卡、TODO或重建环境 |
| 两个项目共用一批容器，随后退出其中一个容器 | 连接配置只有一份，项目软链接引用；工作目录各自独立，默认目标与可选目标直接读取同一共享源；退出统一移除共享登记并清理受影响的项目引用 |
| 两个组件的四臂消融 | 一张目的卡；主表在卡内，参数和逐格证据引用原生配置/产物；阶段不另编号 |
| 后处理失败而生成完整 | 核证后仅恢复受影响阶段；普通失败不另建报告，遗留行动才进 TODO |
| 主表分母订正且论文已采用 | 修来源再改卡，按已知来源和接收人交给采用方；不越界改论文、不加未知下游永久待办 |
| 环境规格升级后接手旧结果 | 能还原旧运行实际环境；不只链接可变路径，不因版本差异全量重跑 |
| 多个写者向共享文档插入条目 | 同一有效锁内重读，各条目保留；不把原子保存当互斥 |
| 已授权独占域阶段完成 | 属主直接接续；有界 worker 仅交付，由委派方验收 |
| 公共调度缺陷在一个实验中暴露 | 修实际公共源，原实验仅记采用；不额外起实验来证明采用 |
| “挑几个 case 看看”后开始新问题 | 明确探索/回归/正式比较，不永久继承固定案例 |
| HTML 展示服务需长期维护 | 维护卡；一次性修复不另立计划系统 |
| 整体任务中已完成一批，剩余工作仍可按原授权处理 | 汇报阶段进展后直接接续，不用首项交付或下一步建议替代整体完成；明确约定的阶段讨论边界仍保留 |
| 修一个路径或一个公共模块 | 修改维护源和受影响入口，沿用有效产物；不默认复制源码树、生成哈希清单或新建release |
| 长任务后段仍会读即将修改的模块 | 判断真实读取影响，安排边界采用或最小隔离；不冻结整个仓库，不自动创建worktree |
| 卡片已改用新评测而留有旧结果 | 现行约定更新，旧结果标清实际口径；当前进展不继续展示过时“尚未开始” |
| 交接写了负责人但接收会话未启动 | 不宣称已交接；原属主/协调者继续跟进，避免双写或无人执行 |

Multi-turn 的四臂消融、早期术语与 TODO 演变、并发整表丢条目、独占域接续、公共后处理提取和路径别名修正支持这些场景。历史核对与完整批准稿保存在维护仓库的设计文档，不将历史容器号、目录或数值当成新项目协议。历史回放不代表本 skill 已经过真实新项目运行验收。
