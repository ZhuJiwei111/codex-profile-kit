# 公共实现、环境和证据使用

## 公共职责

通用参数解析、配置装配、调度、恢复、评分、统计和报告处理归公共源码。沿实际调用链修复，不只补当前实验；已有公共职责的缺陷不必等第二个实验踩坑。实验保留科学配置、特有分析和采用记录；一次性分析出现真实复用或稳定重复后再抽取，不预建框架。

应急修复若暂留执行副本，应在本任务内回公共来源；受阻时登记具体 TODO。修改前判断正在运行的任务是否还会读取受影响的代码、配置或依赖；不要无声改变在途计算，受影响部分在合适边界采用。任务在跑不等于整个仓库不可修改，也不因此默认复制整套执行树。源码已修复和实际任务已采用分别验证；采用利用下一次已授权真实调用，不为证明采用额外启动科研计算。

## 可重建环境

项目的环境准备脚本、依赖规格和锁文件集中放在 `environments/`，例如 `environments/environment-<用途>.sh`，按实际兼容边界拆环境，不按实验编号复制。该目录存放可重建定义，实际安装的环境与包缓存沿平台约定放置；工具要求位于根目录的项目配置保留原位。已有项目迁移时同步更新脚本中的相对路径、实际调用入口和使用说明，不为兼容旧路径保留根目录包装脚本或软链接。以下版本固定要求针对科研依赖；辅助模型 CLI 的安装策略归执行平台，不据此强制固定 CLI 版本。

- 写明用途、支持平台、安装位置、用法及必要检查。复用已有合格环境不需要每次重建；独立短核算不自动触发环境建设。
- Python、包、相关 CUDA wheel 变体、源码依赖和模型修订固定在一份规格。少量依赖可写脚本，较多时消费规格或已有锁文件，不无界升级。 采用版本由项目环境维护者依据实际可用环境确认，安装入口消费同一份约束；普通准备不隐式升级。主动升级同步规格并验受影响能力，不将包版本清单复制进平台 skill。
- 实际环境修复同步进入构建入口；不能只在一个容器手工安装。
- 仅准备所选用途，可选能力显式选择。确有独立准备需要时分别支持环境和模型；不为形式预建所有模式。
- 安装入口用最小必要检查确认该用途必需的能力；核心依赖不可用须失败，不以目录存在、警告后继续或退出码零掩盖缺口。平台收集各执行节点的现有回执，已有同义检查直接复用，不另建验收入口或台账。未变化的合格环境直接使用；新建、相关更新或实际故障只补查受影响部分，不自行降级成另一模型或依赖组合。
- 不热改在跑环境。不兼容升级在独立环境准备，于自然边界采用。
- 独立节点的本地环境准备默认并发；共享的模型下载、源码生成物与其他共享写入按实际冲突点统一处理。同一节点并行准备多个环境时，隔离会被并发修改的包缓存或构建目录。
- 镜像、代理、多机分发、共享盘/节点本地盘选择由平台适配；不写死历史容器、端口或模型通道。

## 轻量记录与运行隔离

默认直接修改公共源码和当前配置。未起跑候选、文档修订、普通修复和技术重试，不自动新建 release、整树副本或递增版本目录。

对实际需要保留的结果，能定位实际输入、关键配置、模型和实现即可；优先引用已有原生记录、可用源码修订和环境规格。只有某项依据将被覆盖且没有其他来源时，才在原运行位置补留该项必要内容。未提交改动需要保留时，局部差异或相关文件即可；不要求每次运行先提交、导出全仓 diff、收齐未跟踪文件、复制包目录或生成哈希清单。原生工具已有用于缓存或断点匹配的标识直接复用，不扩成项目全量校验。

运行隔离只解决真实的并发修改问题：例如长流水线后段还会导入即将改动的模块。优先安排受影响修改在采用边界切换；确需同时运行不同实现时才隔离必要文件或环境，复用已有合适副本，不按实验、节点或每次改动重复复制。需要 worktree 时仍取得创建与位置授权。依赖由项目环境规格维护，不把整个 site-packages 放进每张实验卡。

当前配置表达现在要做的事；原运行记录表达当时用了什么。技术恢复沿用有效产物，修受影响入口，不因路径修复重新包装整套源码或另造科学版本。实际科学条件改变时，在已有结果位置区分其适用范围，避免混算；不因此复制整张卡或整棵实验目录。

## 按实际影响验证

科学验收核对实际输入与配置、约定样本和指标是否完整，以及各阶段自己的产物；唯一写入者与实时占用按现场证据判断。已验收结果直接复用，不因协作交接再做整体验收。

每项额外检查须能说明要排除什么实际错误、影响哪部分结果，以及最小区分方法。

- 实现、输入和协议未变的合格证据复用；只改变评分，不自动重做训练与生成。
- 发现实现、输入、配置、协议、环境或产物错误，按实际影响使相关部分失效。路径、版本或容器差异本身不等于错误。
- 当前进程、资源占用、实际写入者和恢复入口属于实时事实，按现场证据判断；实际无法核实时保留未知，只阻塞依赖该事实的动作。
- 实际条件符合正式方案的合格早期样本、训练进度和检查点可以复用，不因曾用于检查而重复计算。
- 估算用于排程和汇报；偏离时更新。只有明确生效的硬限制才限制停止或资源。改变约定研究目标、主要比较含义或重大资源投入需匹配授权；已有明确决定直接落实，不因旧卡或“冻结”重复审批。

默认称“当前方案”和“本次实际配置”，不把整张卡、整个实验或后续研究称为“冻结合同”。需要保持一致的是某次比较的实际条件，或正在执行的输入；这不限制更新方案、修复实现和继续研究。用户更新设计或退役旧协议后，按新决定更新卡片与后续采用配置，记录方式见 [卡片更新](../../personal-project-journal/references/cards.md#更新和失败)。原结果仍按其实际条件解释；仅重做受变化影响的部分，不因修订卡片自动重训或重评。
