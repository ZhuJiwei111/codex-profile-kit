# 项目入口与本机私有资料

先确定首项真实工作，再引入需要的目录。以下是逐步形成的布局，不是初始化必建清单：

```text
project/
├── AGENTS.md                 项目特有约束、权威入口
├── README.md                 结构、常用用法
├── .gitignore
├── .agent/                   记录能力按需建立
├── environments/             环境准备脚本、依赖规格与锁文件
├── src/                      公共实现
├── tools/                    按需的薄命令入口
├── data/                     数据与来源说明
├── experiments/              实验、研究阶段与维护卡片
├── docs/                     按需的跨实验专题
└── tmp/<任务>/               一次性工作
```

实验编号、卡片结构、产物和分析位置由 [卡片规范](../../personal-project-journal/references/cards.md) 唯一维护；项目待办、术语和历史由 [项目记录](../../personal-project-journal/references/project-records.md) 维护。

AGENTS 只写项目差异，不复制通用 skill；README 导航和解释用法。只有入口难找时才增加索引，只放链接，不手抄状态或结果。跨实验综合文档只维护新的综合判断。报告是使用证据的交付形式，不充当原始证据总仓。既有项目不因安装本 skill 自动迁移目录，新材料服从该项目实际权威位置与已确认决定。

## 本机控制根

`proj/.local/` 归本 skill 定义；proj 是用户选定的本机项目控制目录，可以与本地研究树重合，也可以连接远端权威树。

- `.local/` 保存当前仍需使用的本机私有配置、共享配置引用、项目专用工具入口和运行记录，不承担历史归档。临时操作备份可以短期放置；一次性脚本、检查输出与回退副本的收口由 [临时工作](../../personal-temporary-work/SKILL.md) 负责。需要长期保留的结论与证据回到已有项目记录或产物位置，原生运行记录按所属工具的生命周期处理。
- 容器身份、可选目标、默认目标、连接参数和 SSH 配置集中保存在项目之外的本机私有配置位置；多个项目共用一份，项目在 `.local/` 中通过软链接引用，不各自复制或同步容器清单。实际共享位置由主机配置说明，文件名、字段和解析归平台适配。
- 跨项目通用控制工具在本机公共位置部署一份，项目只配置调用入口和参数，不在各自 `.local/` 留同一脚本的运行副本。远端项目接入时同时配置所用平台的资源查询入口，具体要求归平台 skill。
- 项目只在各自 `.local/` 保存远端工作目录、目标特定目录映射、项目作业状态根等特有信息；默认目标和可选目标直接读取共享配置，不保留项目副本；不把含有项目工作目录的整份配置或整个 `.local/` 链接为共用目录。
- 所属 Git 根忽略整个 `.local/`，包括本机软链接；共享配置也不纳入项目仓库。例如控制根本身是 Git 根时使用 `/.local/`，嵌套时使用对应项目路径。
- 可共享的配置示例和用法单独受版本管理。凭据/私钥沿既有受保护设施保存，`.local/` 不默认成为秘密仓库。
- 本地控制、远端执行时不复制实验树；论文、代码、实验证据等各自只有明确维护位置，不人工同步两份权威副本。
- 私有目录不入库不等于实验原件已备份。大型不可再生产物需要实际持久位置与明确属主。
