# 角色、授权和交接

一个人可承担全部角色。只有独立工作、真实共享冲突或审阅需要时才拆分。

| 角色 | 责任 |
|---|---|
| 长期任务属主 | 范围、执行、证据、记录、授权内验收与收口 |
| 根协调者 | 跨任务综合、优先级、共享冲突、用户选择 |
| 公共实现整合者 | 接受公共修改、检查影响、安排采用 |
| 有界 worker | 明确范围内交付产物与证据 |
| 委派方 | 验收 worker 交付，对整体任务负责 |

独占资源的长期属主在原授权内直接接续训练、生成、评分、修复与恢复，不逐阶段等根批准；共享域使用实际资源互斥入口。估算不是续期配额，空闲设备不授权增加实验。权限缺口只阻塞依赖部分。

有界 worker 不宣布整体任务完成。交回主任务验收的委派使用 [personal-subagent-boundaries](../../personal-subagent-boundaries/SKILL.md)；用户要求可直接讨论的会话时，无论轮数，均使用 [personal-multiline-coordination](../../personal-multiline-coordination/SKILL.md)。本页只规定何时拆角色和结果归属，不复制通信协议。消息、读日志或登记负责人本身不授予执行权限。

研究交接传递当前目标、最新决定和仍需解决的问题，标明引用旧卡中哪些仍适用、哪些已被取代；不把历史配置整体包装为新任务的硬约束。接收方发现冲突时先按明确的现行决定处理，确有未决研究取舍才提问，不机械续跑旧方案。

交接以接收方实际接手并明确接续入口为准。此前由原属主或协调者继续跟进；生效后原属主停止修改已移交写面。通信和回执沿现有协调/委派 skill，不新增逐阶段审批。

后台或跨会话任务按 [卡片生命周期](../../personal-project-journal/references/cards.md) 留恢复依据；观察使用现有授权工具或 supervisor，不能把“观察到了失败”当作重启授权。普通消息不自动发送给其他会话；按已有通信授权和确有行动需要的边界执行。

共享写入统一遵循 [记录写入](../../personal-project-journal/references/writing.md)。工具属于平台适配，不在本 skill 安装或写死某个宿主工具。
