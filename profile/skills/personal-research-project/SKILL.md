# 个人研究项目启动与协作

按用户约定的范围完成研究工作，留下能理解、复用和接续的依据。一个人、一个会话可以承担全部职责；结构和角色随实际需求增加。建齐目录不算完成。

## 开始与接手

- 明确本次问题、授权和完成范围，定位代码、实验、论文及本机配置各自的权威位置。讨论限于只读调查与设计，不启动实验。
- 从当前研究目标和用户最新决定选择方法、对照与评测；旧卡提供参考，不自动约束新研究，不以便于复用或“已冻结”代替研究理由，也不默认追加固定对照或消融。
- 新实验或方法迁移起跑前，将实际方案与用户讨论清楚：做哪些训练或检查、关键方法适配、比较目的和主要投入。内部名称或“检查”不能掩盖新增训练与研究选择；按重要差异提供推荐和备选，有关键未决时使用 [grilling](../grilling/SKILL.md) 集中澄清。方案和执行已获明确授权就直接推进；新出现的实质取舍再讨论，不逐参数或逐阶段重复审批。
- 先查已有代码、环境和合格证据。新项目按 [项目布局](references/project-layout.md) 建立必要入口，不复制整棵示例树。容器连接共用本机私有配置，项目以软链接引用，默认目标与可选目标也由共享配置唯一维护，项目只保存工作目录等特有信息。
- 接手先读本任务规则、卡片、相关 TODO 和实际产物。历史原因才查 JOURNAL；全局接管或跨任务事实矛盾时才用已有全局探针。继续只读变化，不每次全面审计。
- 按研究目的组织实验；多臂、技术阶段、重试和恢复不各建一卡。短核算直接完成，属于已有实验的分析归原实验。默认直接维护当前代码、配置和卡片，不把每次修改变成发布、快照或新版本目录；只按实际结果追溯和运行隔离需要保留必要依据。
- 需要建立或更新记录时，使用 [项目记录能力](../personal-project-journal/SKILL.md)。它唯一维护卡片、TODO、GLOSSARY、JOURNAL 的字段、状态、模板和记录操作；这里不维护第二套。
- 新项目先完成首项真实工作，避免空搭结构；已有明确整体任务时，首项交付只是推进起点。留下结果与必要记录。已知可用环境可直接复用；准备或修改依赖时维护项目的可重建入口。

## 推进已有授权

公共实现、环境与证据复用按 [执行与证据](references/execution-and-evidence.md)；不要把每次实验遇到的通用修复留成实验目录内的补丁，也不要因路径或库版本变化自动重跑。

范围、未决问题、依据和当前交付事实归卡片或已有专题；持续动作进 TODO；重要历史归 JOURNAL。不新建独立 plan 状态体系、反向引用总台账或收口文件。随研究进展更新当前入口、合并重复记录，只保留支撑结论、复用和接续所需的材料。结构调整检查实际受影响的使用方；材料处置遵循本次授权。接手旧项目不自动触发全量重构；特定迁移或清理方案由该项目任务记录承接。

整理研究材料时，从明确保留的论文、结果、数据和服务入口追到必要实物，包括索引引用、软链接链及链接目录的最终目标。删除集合须排除这些实物；不能因其位于旧实验、archive 或临时目录中就判为可删。处置前后检查保留材料的实际可读性，并按用途验证；区分原件可用、仅引用保留和原件缺失。核不清的部分暂留，不默认保留整套旧执行包，也不要求全仓扫描或另建长期台账。

结果订正按记录能力处理。实验原件与复算归实验位置，论文侧维护引用与采用决定；超出当前写面时交给实际采用方。

## 协作与交接

需要独立并行或真实共享冲突时，读 [协作边界](references/collaboration.md)。当前任务属主在已有授权内连续执行、修复、验收和收口；估算偏离、阶段结束不新增审批。额外设备可用不代表获准扩大资源范围或增加实验。

共享文档使用 [记录写入规则](../personal-project-journal/references/writing.md)。skill 规定保证与交接，平台提供可替换入口；不把某台机器的工具、锁原语或路径固化为个人规范。

## 完成与分工

完成以用户约定的整体范围为准，不以自行划分的一批材料或一个步骤为准；可继续的已授权工作直接接续，不转成“下一步建议”等待重复授权。用户明确要求阶段讨论时按约定停下；确有待决或阻塞时说明受影响部分，其余继续。交付须有可追溯依据；确实未完成的事项、后台作业与资源保留明确属主。卡片收口细则由记录能力维护。 本任务产生的一次性脚本、检查输出和回退副本按 [临时工作](../personal-temporary-work/SKILL.md) 完成处置后再交付；仍需保留的材料说明实际用途。

- 通用项目组织归本 skill，记录格式归 `personal-project-journal`。
- 用户可直接交互的 App 会话（含单轮 worker 会话）归 `personal-multiline-coordination`；有界 worker 归 `personal-subagent-boundaries`。
- 实际异常诊断归 `personal-evidence-debugging`，已授权长作业观察使用现有 supervisor；观察不授予重启或扩范围权限。
- 腾讯命令、连接字段和容器恢复由平台能力提供；论文采用与交付、独立评审批次由各自能力负责。未安装的后续 skill 不假称可用，已有授权工具仍可使用。
- 维护或验收本设计时读 [场景验收](references/acceptance.md)；普通任务不加载这份测试清单。
