# TODO、GLOSSARY、JOURNAL

需要哪类记录才建立哪个文件，位置在 .agent/；不预建五件套、工作线副本、级别表或月度目录。尊重既有项目明确约定，不为使用新模板迁移历史。

## TODO：唯一行动入口

持续动作（包括实验动作）进入 .agent/TODO.md。写要完成什么、具体执行人、优先级/等待关系和要求链接；没有相关等待或资源问题就不增字段。不是每条命令都建条目。

示例，仅用于说明分工：

```markdown
- 完成 E001 案例分析 — 乙；定量订正后；要求见实验卡“执行约定”。
```

卡片记录实验负责人、要求和“分析尚未交付”的事实；TODO 记录行动。执行人与卡片负责人相同时可引用。卡片不再维护可勾选副本。本次即可完成的工作不强制 TODO。已约定的行动只要必须留到以后处理，即使只需做一次，也在决定延期时新建或更新现有项目 TODO，写清下一步、执行人、当前阻碍和可恢复的条件。属主在相关作业收口、依赖解除或接手工作时复查该项，条件满足后沿原授权接续。

完成先确认产物/判断已保存到实际归属位置，再移除待办。重要撤回原因记事件；交接时核本任务相关条目，不要求每次全局扫描。登记不授予执行权限，写了接收人不等于实际交接。

## GLOSSARY：共同含义

跨材料术语、符号或别名出现时建 .agent/GLOSSARY.md，按实际语义分组，例如状态与符号、方法与训练、数据与评测、指标与统计、配置与别名。同类放在一起，不空建分组。

一个概念一处定义；别名同行说明，必要时交叉引用。写清含义和必要适用范围/来源；语义改变保留理解历史所需的映射。普通目录名、一次性变量不用全登记。用户汇报与交接首次出现仍解释含义，不能用表已存在来许可内部黑话。

## JOURNAL：重要事件

首次出现需保留的项目事件且已获写入授权时，使用单份 .agent/JOURNAL.md，新记录在前。只有重要变化、原因、根因、路线撤回、教训、交接或成果进入；普通答疑、重复检查与逐阶段进度不记。

最小形态，无强制级别或行数：

```markdown
## YYYY-MM-DD · 事件主题

发生了什么，为什么重要，影响什么；证据指向实际来源。
```

模板不是历史事实。采用所在会话的实际日期/时区；需要区分同日事件时增加时间。历史原意保留，重大订正追加带日期的说明。阅读困难时再归档留入口，不默认月度分层；归档不等于完成，不机械删除仍重要的旧依据。

当前数字与结论归卡片、行动归 TODO，JOURNAL 解释变化而不持续同步进度或下一步。一次性工作有项目影响但不需持续维护时，可以仅在这里留下结果与证据；否则留会话即可。

引用真实复盘用日期/主题和原文或产物入口，行号只辅助定位。区分实测、引用与推断，不把两个事件拼成未经核实的因果。保持秘密、个人敏感资料、大段原始日志在记录之外。
