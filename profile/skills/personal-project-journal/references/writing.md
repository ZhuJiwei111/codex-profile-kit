# 共享记录写入

skill 规定写入保证、触发条件和失败交接；平台提供可替换默认实现。不要把某台机器的文件名、锁原语或目录作为个人通用前提，也不自动安装工具。

同一文件有多个潜在写者时，开始写入前统一入口或由主会话/协调者指定本次整合者。包括会话、worker、后台任务与可能并发保存的编辑器。仅打开阅读不计；用户和会话明确顺序交替编辑时按单写者处理，写前重读。独占写面不增加协调步骤。

可靠写入顺序：
取得有效互斥 → 锁内重读当前内容 → 合并局部修改 → 原子保存 → 回读 → 释放。

所有并发写者必须使用同一机制；原子替换本身不能防止旧快照覆盖，工具不能拦截绕过它的编辑器。选择适用于实际文件系统的已有平台入口；已有适用证据可复用，未验跨主机能力不宣称通过。工具不可用或写入口不能统一时，本次整合者串行合并，其余参与者返回片段和依据，不设永久根写入瓶颈。

锁不跨计算、网络任务或用户等待。锚点冲突/锁超时只暂停相关写入，重读取证，不静默覆盖、不自动夺锁。遗留锁由属主核实原写者与实际宿主后处理，不能仅凭年龄或另一宿主同号 PID 判断可回收。

写后核本次修改及需保留的邻近内容，不把工具回执当实际落盘。不添加常规摘要台账、整表 shadow 副本或自动 Git 操作。只动当前授权写面；无法安全保存时说明缺口与属主，不另建记录体系。
