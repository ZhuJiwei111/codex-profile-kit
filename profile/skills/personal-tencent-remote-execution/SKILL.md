# 腾讯远端容器与执行

把已授权工作落实到正确的腾讯容器、环境和资源。通用研究组织与 `proj/.local/` 的私有性、Git 忽略归 `personal-research-project`；卡片、TODO、GLOSSARY、JOURNAL 的记录规则归 `personal-project-journal`。本 skill 不维护第二套项目计划或作业状态。

## 用户常用请求的默认范围

- **“接入／初始化这个容器”**：完成连接登记、全部成员节点的项目默认环境准备和资源保护接管，使其可用于后续任务；不是只验证 SSH 或建完环境。明确的节点子集或排除项只影响对应部分：“暂不安装环境”不取消保护接管，“暂不挂保护”不取消环境准备；“只检查”保持只读。
- **“检查当前容器／汇报资源”**：查看当前登记资源及相关任务、保护和可调度情况；检查本身不启动任务、补保护或变更资源分配。
- **“退出／退役／移除这个容器”**：清理该目标的活动连接与失效资源入口；不是只退出当前 SSH，也不要求先证明平台实例释放。

接入执行者负责把已授权初始化做完，并在现有记录中明确保护维护归属；未分配科研任务不等于无人接管，也不需要另开常驻会话。科研分配仍由用户或已授权协调者决定。

## 连接与存储

- 按本次请求读取项目连接登记、远端相关 AGENTS 和实际执行入口；继续工作只读变化。dev README 保存当地命令、配置位置与实现，不将具体别名、容器号、挂载路径写死在 skill。
- 控制端的容器身份、可选目标、默认目标、连接参数和 SSH 配置使用本机共享私有登记，项目在 `proj/.local/` 以软链接引用；项目配置只保留工作树、目标特定目录、项目状态根等特有信息。具体路径、字段和解析由实际平台入口维护，不在 skill 定义第二份 schema。普通命令、交互、新 worker、新服务优先使用本次明确指定的目标，否则读取共享默认目标；据项目配置确定工作目录。认证内容不进入工作记录。
- 项目复用已接入容器时，复用已有连接与合格环境、保护，只补本项目确需的缺项，不重复首次初始化。共享连接不授予其他项目资源或文件的使用权。迁移混有项目字段的旧连接配置时，同时适配实际调用方并验证目标及工作目录。
- 新增容器不自动替换默认目标；用户指定主容器时只更新共享默认值，所有项目的新调用直接采用。已有作业、服务和观察绑定其实际执行实例；改变默认目标不迁移它们。已知任务换宿主属于明确恢复或迁移，不以默认值覆盖旧绑定。
- “退出容器”统一从共享配置移除该容器，并清理受影响项目中的失效目标引用；不另设项目级解除引用流程。这里的失效引用不包括 supervisor 作业定位：保留原 `target/state_root`，后续读取或清理按插件契约处理。完整清理该实例的活动连接登记、对应 SSH 配置、精确 SSH 信任残留和失效转发，以及现有资源／保护／服务记录中的失效引用；无需先证明平台释放，不操作平台实例或停止其进程。共享模型、实验产物与项目共用客户端密钥保留。退出默认目标时消除失效默认引用，采用已明确的替代目标；未指定替代时留空，后续仍可显式选择目标，不阻塞退出。
- 退出后再次接入一律作为新实例，即使 IP、端口或物理节点相同，也不继承旧身份、PID 或资源占用。正常退出已清理旧信任，不再例行索要旧实例证明；确有未清理残留时，仅处理本次明确新实例对应的精确项。共享盘继续可见不代表旧进程仍在。
- 模型权重（包括评测依赖的 backbone 权重）、大数据、代码和持久证据放共享盘；运行环境与包缓存放节点本地盘。共享模型根与项目引用由当地配置维护，不在 skill 固定目录层级，也不因接入新容器自动搬迁历史模型。版本规格、重建与检查规则归 `personal-research-project/references/execution-and-evidence.md` 的“可重建环境”；本 skill 负责在腾讯节点落实这些入口。

## 新容器首次接入

登记本次授权目标，确认可用登录入口、共享盘和项目工作树，沿 dev 的节点解析和 GPU 查询入口读取成员节点及实际卡数，不假定每节点八卡。已有项目免密入口能用就复用；需要设置项目认证时沿授权入口办理。具体配置路径、命令和 Bash 加载方式归 dev README。初始化调用平台统一准备入口，由它组合现有节点分发、环境和保护能力；不让 GPT 每次重新拼装逐节点 hold。普通环境安装和日常加载不隐式接管资源。

1. **接管保护。** 在本次接入的全部成员节点核实际占用，复用已合格保护，为已确认空闲的卡接入现有 hold；这是默认初始化的一部分，不等你再次要求“挂 hold”或先分配科研任务。保护依赖具备后尽早落实，可与不争用资源的环境准备并行，不让空闲卡等整套科研环境装完。实际科研任务或服务已占用的卡沿原属主和保护方式处理，不能叠加普通 holder。复用原生保护入口的实际就绪与覆盖结果，只对缺项或矛盾补检查；进程存在本身不等于保护生效。已占用或未知卡如实列出并沿实际属主处理，不冒充已完成保护。
2. **准备环境。** 从项目工作树调用现有入口的环境准备模式，并行补齐该容器全部成员节点缺失的项目环境与辅助 CLI；清单由项目配置选择，只有本次明确指定子集时才缩小范围。清单已包含 CLI 就不再单独安装。符合规格的现有环境与共享模型直接复用，模型缺项由对应准备入口处理；修复只覆盖实际失败项，具体命令见 dev README。
3. **重登一次。** 收取准备入口已有的各节点结果，不重做其已通过的同义检查。对本次新增或修改自动加载配置的交互登录节点，各从项目目录经实际登录入口重登一次，确认默认环境与所需命令可用；已有未变化的合格配置不重复验收。

接入完成以连接可用、所选节点环境就绪、保护已接管和现有资源记录反映实际情况为准；科研任务尚未分配可保持待分配状态。可自行修复的缺项在本次授权内补齐，不能只做一部分便停下；真实阻塞说明影响范围，继续其余独立工作。

保护效果核验是接管的一部分；首次接入不默认追加完整科研样本、GPU 推理压测、重复 CLI 版本审计或凭据检查。这些随实际任务需要验证。安装成功不等于已登录或模型可调用，首次派发用本次真实任务的有效回执验收，不另发一轮无任务目的的测试调用。新清单不自动升级其他容器。

环境和权重按用途准备，不将无关模型下载捆入默认清单；复用共享权重、固定版本 wheel 和已有缓存，独立节点并行处理。调整共享模型默认位置时，同时更新相关运行入口，不能只改下载落点就宣称默认已统一；普通接入复用有效配置，不全面审计其他入口。具体目录沿现行 dev／项目约定，不另造节点环境路径。安装或下载异常按日志、实际进度和链路定位，只修失败项；权重下载慢不等于环境要重建，也不只留下“下次再查”的建议。

准备入口负责依赖安装、必要检查与并发协调，平台复用其回执。同一准备仍在运行时接续观察，不重复启动；互斥未释放不等于任务仍在运行，按原执行记录核实后处理异常，只处理受影响部分。实现与故障修复归 dev 或项目入口，不增加第二套初始化工具、回执或检查流程。

## 日常环境与辅助模型

新容器首次准备 CodeBuddy 时安装发布渠道的最新版；已有可用安装直接复用，不为短生命周期容器另建自动升级机制。CLI 安装策略与科研依赖固定版本分开；不因 wrapper 更新自行推断上游 runtime 已更新。具体版本与平台生命周期事实留在 dev，不在 skill 固定数字。

`dev_env.sh` 加载已有环境、配置及命令。缺少目标环境时定位具体缺口；已获环境准备授权就调用项目入口补齐，否则说明所缺依赖和所需授权。非交互任务按自身入口显式加载所需环境；环境准备入口可在目标环境尚未存在时运行。

辅助模型默认通过 CodeBuddy CLI；当地入口与模型简称映射见 dev README。简称、模型名称和实际接口 ID 的映射只由 dev 工具配置维护；用户说 `ds` 时按该配置解析，不在 skill 或每个科研项目复制模型版本。用户显式指定的模型覆盖默认值；未知角色名报错，显式接口 ID 交由原生 CLI 校验，不静默换模型。配置更新只影响新派发，已派发任务按启动选择与实际回执核对，不追溯改写。

DS 可承担有界 worker 或讨论，Claude 可承担讨论或审查；不要求每项任务双重审阅。由调用方设置任务实际工作目录，短任务说明走标准输入，大材料按授权路径引用，保留必需原文与原生输出；不把完整多份 skill、整段历史和重复说明一并堆进提示词。工作目录外的授权材料通过原生目录授权提供；范围不适合开放整个目录时，准备仅含所需材料的只读审阅快照。只读审阅限制为读取工具，不通过关闭权限检查解决材料不可见。交付核对实际阅读范围与权限拒绝；必需材料未读到时补齐本次授权范围后继续，不能把部分审阅当作完整验收。

有界委派的任务边界、交付要求与验收复用 [personal-subagent-boundaries](../personal-subagent-boundaries/SKILL.md)，委派形式与审阅者选择仍归该 skill，本节只适配辅助 CLI 调用和模型解析；长期会话协调按需复用 `personal-multiline-coordination`。原属主承担验收与后续。远端辅助 CLI 可显式接受有界工作；不因控制端离线或观察事件自动启动 AI 接班。科研 API 请求使用其已有公共入口，辅助模型默认变化不修改冻结的评测模型或协议。

需要指定推理模式时使用当前 CLI 的原生选项，具体用法见 dev README。

交付须有有效最终结果；输出截断或只有思考不能当完成。调用异常按 `personal-evidence-debugging` 核对实际请求和原生回执。若可能已产生写入或执行，先核实际结果。确认可安全重试时，在已有授权内恢复。定位到平台实现缺陷时，在对应维护源修复，并用能复现该缺陷的材料验证。大材料仍按任务需要完整提供，不因模型故障删掉必需证据，也不自动换模型。

## 长作业交给 supervisor

符合已安装插件适用条件的已授权非交互长作业使用 `personal-long-job-supervisor:supervise-long-jobs`；短命令不因远端执行或环境准备而强制使用监督器。读取已安装插件的 `SKILL.md`，远端工作再读插件内 `references/remote-access.md`。依赖新行为前核对控制端和远端实际执行版本，不以候选维护源代替已部署契约，也不热改健康作业已加载的 worker。插件负责启动请求身份、脱离 SSH 的执行、健康采样、日志、持久事件、确认及观察恢复；本 skill 只负责腾讯目标、工作树、环境和资源适配，不另实现任何一项。

共享容器登记、共享默认目标与项目工作树由本平台适配解析；插件专属配置按其接口填写，不另定义字段。原生 job 记录唯一保存运行事实，本地定位由插件生成，可重建；卡片只引用结果和必要入口。插件运行目录可清理；其中仍需持久引用的证据，在清理前移交原任务产物位置并更新引用，不把运行目录当作实验归档。

原生作业、事件消费、断连重连与观察恢复遵循插件契约。腾讯适配负责把当前可用连接与共享盘位置交给插件，不据默认目标变更迁移已有运行任务。容器释放后的计算恢复由原属主核实际产物、检查点和既有授权决定；观察恢复不代替计算恢复。GPU 无法可靠归因时不能解释为空闲，使用任务已有的实际请求或产物证据，不另造心跳或观察器。

## 资源利用与保护

每个接入腾讯计算资源的项目都要配置可用的本地跨容器查询入口，作为项目接入的一部分；接手已有项目时补齐实际缺项。入口复用本机公共工具及共享连接登记，显式传入本项目配置和查询范围，不依赖另一个项目的私有工具目录，也不逐项目复制脚本。GPU 采集及归属判断由远端平台实现，本地负责发起调用、汇总与展示；不为查询建立容器间互信。主机工具位置归 HOST_LOCAL，平台实现与部署方式归 dev，项目 README 留实际命令。历史来源机器等非计算目标不纳入默认 GPU 查询。首次配置用一次只读查询确认目标和返回结果；已有未变的合格入口不重复验收。

按问题查资源：普通工作查相关节点；“当前容器情况”、全局资源利用、跨任务分配或真实冲突查当前登记的已授权资源池。汇报沿现有资源记录关联容器、节点／卡数、实际科研任务或服务、保护覆盖和可调度范围，并说明观察时间及不可达／未知项；不新建资源台账。接入或退出后更新受影响记录和汇总，不为更新总数重验其他健康容器。

跨任务分配沿现有记录按实际任务列出节点和卡段，共享节点按卡段计数。分配前核授权、实际归属与可用范围，由对应属主更新该记录即可交接。

执行入口统一消费平台的当前目标与成员节点信息，结合现场实例身份、GPU UUID 和实际占用确定本次卡段；任务配置只保存本次采用范围与运行事实。资源身份、按卡互斥、输出唯一性、保护让路与退出归还由公共执行入口实现。平台接入或退出后，现行调用方同步采用该入口；用户明确退役的旧接口和独立节点名单一并退出现行调用。

登记缺项、实例变化或保护接口不匹配时，先诊断具体原因，在已有授权内修正对应登记、配置或实现；只有定位到公共入口缺陷时才修改源码并验证受影响调用方。真实归属冲突或授权缺口交协调者决定。还有独立可做的调查、准备或修复时继续推进。资源检查与科研输入、评分证据检查各随实际依赖执行，已验收且未变化的证据直接复用。

需要预计何时可调度时，区分本任务还卡、已排后继结束后可再次分配、整项作业完成和容器到期。按当前进度、实测速率及已排后继给出预计时间，注明观察时间和关键假设。缺少后继速率可参考可比工作；仍无法估计时说明缺什么、到哪个节点能更新。队列或进度明显变化时修订。预计时间不构成预留或交接授权。

显存、设备利用率、进程名称、节点不可达都不能单独证明空闲或归属；缺乏证据的卡不计可用。GPU 进程映射不完整时，继续核相关任务原生记录、实际进程或产物，能确认的归属照实说明，不能只报 unknown 就结束已要求的调查。仍无法确认的只限制对应资源操作。设备利用率含保护负载，科研进展看真实任务或服务请求；只有 holder 的卡是受保护的空闲资源，不等于科研忙碌，是否可分配仍依资源边界。

原属主在独占域内直接接续已授权阶段。已有明确跨任务交接安排和可执行入口时，释放后直接按安排交接，不再等协调者重新批准；争用、优先级冲突、跨授权范围或科学变化才协调。充分利用资源是让就绪的已授权工作取得资源，不为填满 GPU 新增实验、样本或改变冻结训练配置，也不为扩容强迁不支持弹性的健康任务。为同一任务加卡前，确认入口支持并行扩容，辅助进程沿用同一原子队列、领取机制和样本标识，避免重复写出。

需要控制端离线时仍能接续的确定步骤，在起跑前纳入任务自身执行入口；supervisor 只观察，不编排后续阶段。需要新判断的后继由原属主在线处理，不因此另建值守或自动 AI 接班。

保护随资源属主维护，服务保护随服务属主维护。保护不表示科研任务预订，也不计科研利用率。启动、停止和让路必须限定在已授权的节点、卡及对应进程身份；查询所有节点不授权操作所有节点，不按同名进程批量清理。

- 空闲卡保护在真实工作需要资源时让路。
- 批处理服务有明确消费边界时，优先在原执行入口中处理保护切换，不要求每请求人工确认。
- 持续在线服务需要同卡保护时，采用适合实际服务并已验证的共存配置，明确请求恢复后的处理方式。尚无合格配置时，服务属主在已有授权内做有界首次验证，核真实请求恢复、服务影响与保护实效后采用；超出原授权的资源或服务影响再由用户决定。共存保护异常时，先停止保护进程并确认它已退出，再保持保护停用并继续服务；无法确认让路则阻止依赖让路的请求。小显存不代表低计算影响，普通满负载 holder 不直接作为默认共存方案。参数、实际效果及适用环境归 dev 或服务自身记录，不在 skill 写固定阈值或逐服务重复审批。

工作结束或进入不再需要 GPU 的阶段，保存必要状态并确认所属写入和进程边界后，归还所属资源池；专用域不会因此自动变成公共域。已有就绪任务及交接授权时直接交接，否则对仍需保留的本次资源恢复原有保护，不把空卡留到下一次用户提醒；明确退出或不保留的资源不补保护，不触及其他任务。平台回收条件按实际平台和用户提供的口径，不把本地采样次数等同于平台告警。

## 服务与收口

对外展示直接使用容器的平台透传入口 8080/8081，不默认建立或维护本机转发；内部服务可使用其他端口。只有任务确实需要控制端本地访问时，才采用相应转发。绑定前核已有服务，验收访问到的实际内容；默认目标变化不迁移健康服务。迁移须验证新入口并处理原服务的交接，不按端口号批量停止其他服务。

持续服务的用途、启动方式、实际宿主和访问入口归已有维护卡或原生服务记录；引用连接目标，不复制 SSH 参数或人工运行状态。容器释放或服务迁移时，由服务属主更新该记录的失效入口或新位置；不保留指向已移除目标的有效服务入口。短命服务不为登记单独建卡。

收口只交接发生变化的属主、作业/资源/服务、证据入口和未完成动作，项目交接复用 `personal-research-project`，记录与共享写入复用 `personal-project-journal`。保存、部署、实际采用和测试分别报告；现行工具不满足规则时明确实现缺口，不把写下规则当作已切换。
