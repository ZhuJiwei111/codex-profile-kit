# 腾讯远端容器与执行

把已授权工作落实到正确的腾讯容器、环境和资源。通用研究组织与 `proj/.local/` 的私有性、Git 忽略归 `personal-research-project`；卡片、TODO、GLOSSARY、JOURNAL 的记录规则归 `personal-project-journal`。本 skill 不维护第二套项目计划或作业状态。

## 连接与存储

- 按本次请求读取项目连接登记、远端相关 AGENTS 和实际执行入口；继续工作只读变化。dev README 保存当地命令、配置位置与实现，不将具体别名、容器号、挂载路径写死在 skill。
- 控制端 `proj/.local/connections.json` 登记当前目标、默认目标和工作树，同目录私有 SSH 配置负责传输。普通命令、交互、新 worker、新服务优先使用本次明确指定的目标，否则读取默认目标。认证内容不进入工作记录。
- 已有作业、服务和观察绑定其实际执行实例；改变默认目标不迁移它们。已知任务换宿主属于明确恢复或迁移，不以默认值覆盖旧绑定。
- SSH 不通不等于释放。确认实例释放后，移除有效连接登记及对应的精确 SSH 信任残留、失效转发；不为历史产物保留死路由。端点再次分配时重新接入。共享盘可见不代表旧进程仍在，PID 不跨实例继承。
- 模型、大数据、代码和持久证据放共享盘；运行环境与包缓存放节点本地盘。版本规格、重建与检查规则归 `personal-research-project/references/execution-and-evidence.md` 的“可重建环境”；本 skill 负责在腾讯节点落实这些入口。

## 环境与辅助模型

`dev_env.sh` 只加载已有环境、配置及命令，不隐式安装、预热、启动后台或同步认证。缺少目标环境时报告具体缺口，不静默切换另一套环境。项目维护唯一的默认环境清单和默认激活环境；已授权的新容器创建或接入包含按该清单准备容器全部节点，不逐节点重复申请授权。已有任务遇到节点环境缺失时，按原规格补齐受影响节点；默认清单变更不自动升级其他已接入容器。首次准备只有明确指定节点子集或专项测试时才缩小范围；修复只覆盖实际受影响节点。“全部节点”指该容器成员，不是所有已登记容器。模型共享准备一次，环境逐节点安装。

按项目环境规则收齐受影响节点的必要准备结果，不能用 launcher 成功代替其余节点完成；已有合格检查直接复用，常规加载和接续不重复全量验收。准备入口不能依赖尚待创建的环境；辅助 CLI 若属于项目默认准备清单，同样覆盖全部节点；登录与凭据仍按实际使用节点单独处理，不自动复制。安装完成不等于已登录或实际任务已验收。

辅助模型通过现有 tclaude 入口。简称、模型名称和实际接口 ID 的映射只由 dev 工具配置维护；用户说 `ds` 时按该配置解析，不在 skill 或每个科研项目复制模型版本。用户显式指定的模型覆盖默认值；未知角色名报错，显式接口 ID 交由原生 CLI 校验，不静默换模型。配置更新只影响新派发，已派发任务按启动选择与实际回执核对，不追溯改写。

DS 可承担有界 worker 或讨论，Claude 可承担讨论或审查；不要求每项任务双重审阅。派发明确任务、材料、允许写面、交付和适用检查；由调用方设置工作目录，长文本走标准输入，大文件按路径引用，保留原生输出。工作目录外的授权材料通过原生目录授权提供；范围不适合开放整个目录时，准备仅含所需材料的只读审阅快照。只读审阅限制为读取工具，不通过关闭权限检查解决材料不可见。交付核对实际阅读范围与权限拒绝；必需材料未读到时补齐本次授权范围后继续，不能把部分审阅当作完整验收。讨论验有效结论与依据，修改验真实 diff 与检查，审阅验实际阅读范围；退出码零不等于交付。

有界委派复用 `personal-subagent-boundaries` 的任务边界，腾讯平台的 CLI 选型与模型配置以本节为准；长期会话协调按需复用 `personal-multiline-coordination`。原属主承担验收与后续。远端 tclaude 可显式接受有界工作；不因控制端离线或观察事件自动启动 AI 接班。科研 API 请求使用其已有公共入口，辅助模型默认变化不修改冻结的评测模型或协议。

## 长作业交给 supervisor

已授权的非交互长作业使用 `personal-long-job-supervisor:supervise-long-jobs`，读取已安装插件的 `SKILL.md`，远端工作再读插件内 `references/remote-access.md`。依赖新行为前核对控制端和远端实际执行版本，不以候选维护源代替已部署契约，也不热改健康作业已加载的 worker。插件负责启动请求身份、脱离 SSH 的执行、健康采样、日志、持久事件、确认及观察恢复；本 skill 只负责腾讯目标、工作树、环境和资源适配，不另实现任何一项。

连接登记中的目标、默认目标和工作树由本平台适配维护；插件专属配置按其接口填写，不另定义字段。原生 job 记录唯一保存运行事实，本地定位由插件生成，可重建；卡片只引用结果和必要入口。插件运行目录可清理；其中仍需持久引用的证据，在清理前移交原任务产物位置并更新引用，不把运行目录当作实验归档。

原生作业、事件消费、断连重连与观察恢复遵循插件契约。腾讯适配负责把当前可用连接与共享盘位置交给插件，不据默认目标变更迁移已有运行任务。容器释放后的计算恢复由原属主核实际产物、检查点和既有授权决定；观察恢复不代替计算恢复。GPU 无法可靠归因时不能解释为空闲，使用任务已有的实际请求或产物证据，不另造心跳或观察器。

## 资源利用与保护

按问题查资源：普通工作查相关节点；全局资源利用、跨任务分配或真实冲突才查已授权资源池。显存、设备利用率、进程名称、节点不可达都不能单独证明空闲或归属；缺乏证据的卡不计可用。设备利用率含保护负载，科研进展看真实任务或服务请求。

原属主在独占域内直接接续已授权阶段。已有明确跨任务交接安排和可执行入口时，释放后直接按安排交接，不再等协调者重新批准；争用、优先级冲突、跨授权范围或科学变化才协调。充分利用资源是让就绪的已授权工作取得资源，不为填满 GPU 新增实验、样本或改变冻结训练配置，也不为扩容强迁不支持弹性的健康任务。

需要控制端离线时仍能接续的确定步骤，在起跑前纳入任务自身执行入口；supervisor 只观察，不编排后续阶段。需要新判断的后继由原属主在线处理，不因此另建值守或自动 AI 接班。

保护随资源属主维护，服务保护随服务属主维护。保护不表示科研任务预订，也不计科研利用率。启动、停止和让路必须限定在已授权的节点、卡及对应进程身份；查询所有节点不授权操作所有节点，不按同名进程批量清理。

- 空闲卡保护在真实工作需要资源时让路。
- 批处理服务有明确消费边界时，优先在原执行入口中处理保护切换，不要求每请求人工确认。
- 持续在线服务需要同卡保护时，采用适合实际服务并已验证的共存配置，明确请求恢复后的处理方式。尚无合格配置时，服务属主在已有授权内做有界首次验证，核真实请求恢复、服务影响与保护实效后采用；超出原授权的资源或服务影响再由用户决定。共存保护异常时，先停止保护进程并确认它已退出，再保持保护停用并继续服务；无法确认让路则阻止依赖让路的请求。小显存不代表低计算影响，普通满负载 holder 不直接作为默认共存方案。参数、实际效果及适用环境归 dev 或服务自身记录，不在 skill 写固定阈值或逐服务重复审批。

工作结束或进入不再需要 GPU 的阶段，保存必要状态并确认所属写入和进程边界后，归还所属资源池；专用域不会因此自动变成公共域。是否补保护按原有资源保留安排处理，不触及其他任务。平台回收条件按实际平台和用户提供的口径，不把本地采样次数等同于平台告警。

## 服务与收口

对外展示直接使用容器的平台透传入口 8080/8081，不默认建立或维护本机转发；内部服务可使用其他端口。只有任务确实需要控制端本地访问时，才采用相应转发。绑定前核已有服务，验收访问到的实际内容；默认目标变化不迁移健康服务。迁移须验证新入口并处理原服务的交接，不按端口号批量停止其他服务。

持续服务的用途、启动方式、实际宿主和访问入口归已有维护卡或原生服务记录；引用连接目标，不复制 SSH 参数或人工运行状态。容器释放或服务迁移时，由服务属主更新该记录的失效入口或新位置；不保留指向已移除目标的有效服务入口。短命服务不为登记单独建卡。

收口只交接发生变化的属主、作业/资源/服务、证据入口和未完成动作，项目交接复用 `personal-research-project`，记录与共享写入复用 `personal-project-journal`。保存、部署、实际采用和测试分别报告；现行工具不满足规则时明确实现缺口，不把写下规则当作已切换。
