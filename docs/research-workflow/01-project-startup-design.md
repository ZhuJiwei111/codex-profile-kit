**一、名称、职责与触发**

名称：**个人研究项目启动与协作**。

它负责从一个人、一个会话、一个研究问题出发，完成首项真实工作，并留下可理解、可复用、可接续的结果。适用于新项目启动、已有项目接手，以及研究工作中的任务组织、公共实现、记录归属和协作交接。

典型请求：

> “开始一个研究项目，先验证这个想法。”  
> “接手这个实验，看看做到哪里并继续。”  
> “这些实验怎么组织，哪些代码应该共用？”  
> “整理项目记录，让下次会话能接着做。”  
> “把这项工作交给另一个会话或 worker。”

判断是否由它负责，看请求是否涉及**项目如何开展、事实放在哪里、谁负责继续，以及怎样交付**。普通查文件、一次核算和结果解释直接完成，不因使用本 skill 自动创建目录、卡片或协作角色。

输入包括研究问题、现有材料、实际授权、相关工作树与当前任务状态。输出应是：

- 首项真实工作的结果，或接手任务取得的实质进展。
- 能追溯结果的配置、产物和采用依据。
- 与实际工作规模相称的记录。
- 有明确属主的剩余事项。

目录建齐、文档写齐不构成完成。讨论和审阅请求只授权相应检查，不自动启动实验。

本 skill 负责**何时建立结构、事实归属与交接**。具体记录格式由重构后的项目记录 skill 唯一维护；平台执行、论文采用和独立评审分别交给后续三个 skill。

**二、最小开始方式与目录**

新项目先确定研究问题、本次授权、首项交付和各类材料的权威位置，再查已有代码、环境与证据，直接推进最小真实工作。

下面是按需形成的结构，不是首日必须创建的清单：

```text
project/
├── AGENTS.md
├── README.md
├── .gitignore
├── .agent/
│   ├── TODO.md
│   ├── GLOSSARY.md
│   └── JOURNAL.md
├── environment-<用途>.sh
├── environments/                    依赖规格较多时使用
│   └── <用途>.txt                    或项目已有锁定格式
├── src/                             公共实现
├── tools/                           按需：薄命令入口
├── data/                            数据及来源说明
├── experiments/
│   ├── E001-简短实验目的/
│   │   ├── README.md                 实验卡
│   │   ├── configs/                  实际配置
│   │   ├── outputs/                  原生执行产物
│   │   └── results/                  汇总、分析、图表
│   └── results-viewer/               持续维护对象，不占实验编号
│       └── README.md
├── docs/                            按需：跨实验专题和用法
└── tmp/<任务>/                      一次性工作
```

`AGENTS.md` 保存项目特有约束与权威入口；`README.md` 提供项目结构和常用用法。两者不复制通用 skill 正文。

不默认建立实验总索引、结果总表、独立分析总目录、结论台账、计划目录或公共自动化框架。只有导航困难、跨实验综合或真实重复工作出现时才增加：

- 索引只维护入口，不手抄状态和数字。
- 综合文档维护新的跨实验判断，引用原卡结果。
- 公共脚手架承接已有公共职责或实际复用，不为可能出现的需求提前建设。

现有项目接手时，先定位其事实来源和当前任务，不因采用新 skill 就迁移历史目录。

**本机私有配置**

本机项目控制根使用：

```text
proj/
└── .local/
    ├── connections.json             腾讯适配中的登记示例
    └── ssh_config                   腾讯适配中的连接配置示例
```

本 skill 定义 `.local/` 的位置、用途及 Git 忽略约定；具体文件、字段、别名和目标解析由平台 skill 定义。

- `.local/` 保存本机连接登记、机器路径等不可移植配置，整个目录由所属 Git 根忽略。
- 可共享的配置示例和用法单独受版本管理。
- 凭据和私钥使用既有受保护设施；`.local/` 不默认成为秘密仓库。
- 本机控制根可以与本地研究工作树重合，也可以连接远端权威树；连接远端不意味着复制实验仓库。
- 每类事实明确维护位置，不建立两份需要人工同步的权威副本。

**三、实验卡：按研究目的聚合**

一项可独立解释的实验目的使用一张卡。目录采用稳定编号加简短目的，例如：

`experiments/E001-两个组件的贡献/`

同一问题中的多臂对照、训练、生成、评分、技术重试和相关分析归同一张卡。不默认给每个阶段另造 run-id；工具已有的任务标识直接引用。

例如，检验两个组件及其组合的四臂消融，可以在一张卡中说明完整方法、分别去掉一个组件、同时去掉两个组件的比较。技术阶段不会把这个研究问题拆成多张卡。

卡片需要回答以下四类问题。**下表与状态是共同设计的审阅内容；实际落地时，字段、状态和模板只在项目记录 skill 中维护。**

| 部分 | 核心内容 | 有实际需要时补充 |
|---|---|---|
| 目的与设计 | 要回答的问题、比较对象、变化因素、结果如何回答问题 | 假设、混杂、未决问题、关联实验 |
| 执行约定 | 实际授权范围、输入和配置来源、比较单位、主要判据、完成范围 | 资源估算、明确硬限制、检查点选择 |
| 当前进展 | 实验负责人、状态、已完成及尚未交付的事实 | 持续待办链接、阻塞原因、实际作业与恢复依据 |
| 结果与判断 | 主要结果表、来源、当前结论及适用范围 | 长分析、订正、停止原因、后续研究问题 |

状态使用：**设计中、待执行、执行中、暂停、已收口**。阻塞在卡内说明原因及解除条件，不另扩展状态表。状态描述事实，不触发额外审批。

字段随信息形成补齐。开始执行前明确保证本次比较正确所需的内容，不要求预先设计完整研究路线。未决问题留在对应设计或执行约定中；需要处理的动作进入 TODO，没有问题时不设空栏。

**卡片与产物分工**

- `configs/` 保存实际执行配置；完整参数不再手抄进卡片。
- `outputs/` 接受工具原生布局，保存日志、图像、评分、检查点等。
- `results/` 保存汇总、分析代码和图件；长分析按需放 `analysis.md`。
- 卡内保留主要结果表及当前结论。表格来自同一汇总来源并校验；分母、比较单位和解释结果所需的信息必须清楚。
- 逐格证据、完整参数与执行细节引用原生记录。
- 长分析解释判断过程，不再独立维护另一份“最新结论”。
- 大型产物可以放在合适的持久存储中，引用实际位置；路径指针不代表产物已有备份。

不把证据统一堆进 `reports/data/runs/`。证据随实验目的或维护对象组织，报告只是使用这些证据的交付形式。

**拆卡规则**

- 新的独立研究问题或因果比较：建立关联卡。
- 同一目的下的补样本、技术重试、容器迁移和恢复：留在原卡。
- 改变评测口径：明确区分新旧口径，保留旧结果；形成独立问题时再拆卡。
- 共用对照：引用同一份已接受产物，不重复计算为独立证据。
- 论文决定采用哪个既有结果：由论文侧记录，不因此新建实验卡。

短分析不因运行了代码就建卡。回答已有实验问题的归原卡；一次性且有项目影响的核查可记 JOURNAL；简单解释留在会话即可。

HTML 展示服务等持续维护对象使用无编号目录，记录用途、入口、负责人、依赖、状态与交付标准，不强套科学消融字段。

**四、更新、异常、订正与收口**

实验负责人维护卡片，执行工具产生细粒度运行记录。在范围、授权、负责人、阶段交付、阻塞、证据、结论或收口发生实质变化时更新，不复制每次进度。

**接续与失败**

会留下后台进程、跨会话执行，或失败后需要恢复的工作，启动时留下能定位实际执行和产物的入口，引用实际宿主、作业、日志、检查点及状态记录。暂停和交接时核实变化与接续条件；短时工作不强制填恢复块。

发现异常失败后：

1. 任务属主核实受影响阶段、有效产物和资源状态。
2. 更新必要的任务事实。
3. 已有授权内可以直接修复或恢复的，继续处理。
4. 尚未解决、需要跨会话接续、外部依赖或用户决定的，进入 TODO 并明确接收人。

普通失败不强制另写 JOURNAL 或失败报告。后台事件由实际执行和监测入口提供，不承诺会话离线后仍有 AI 自动判断。发现无明确接收人的遗留任务时，由当前主会话或协调者明确接续归属，不凭状态文件猜测它仍在运行。

**结果订正**

订正顺序固定为：

> 原始来源或复算 → 卡内结果与判断 → 已知下游采用位置 → 剩余待办。

保留解释旧结果的依据。重要订正记录日期、原因和影响范围，不追溯改写历史事实。实验复算与原件留在原实验位置；论文侧维护引用和采用决定。

采用结果的位置留下来源卡或原始证据引用。实验属主负责修正来源、说明影响并明确已知接收人；采用方负责更新其维护的表述和产物。超出权限时，通过已有授权渠道交接，不直接改写他方材料。尚未完成的实际订正进入 TODO，不建立反向引用总台账，也不因可能存在未知下游而制造永久待办。

只在形成项目级教训或重要决定时另记 JOURNAL，不把一次订正重复写成多份状态记录。

**收口**

收口要求：

- 已交付约定范围，或用户明确停止并说明实际完成范围。
- 结果可追溯，结论与证据强度相称。
- 所属写入、作业和资源已妥善结束或交给明确属主。
- 剩余事项有明确去向。

阴性结果、未达预期和被否定的假设可以正常收口。收口写在卡内，不另建 `closeout.md`。聊天结束、监测退出或 launcher 成功不等于实验完成。

**五、TODO、GLOSSARY 与 JOURNAL**

三者由项目记录能力统一提供维护规则，各自只承担一类事实。

**TODO：统一行动入口**

持续待办，包括实验中的待办，都集中登记。例如：

> 完成 E001 的案例分析；执行人乙；定量订正完成后处理；要求与产物位置见实验卡。

卡片记录实验负责人、要求和当前交付事实；TODO 记录具体动作、执行人及安排。行动执行人与实验负责人可以不同，相同时可以引用。

卡片不另维护一套可勾选行动清单。不是每条命令都变成 TODO；一次即可完成的工作不强制建立待办文件。

完成时先确认交付已经进入卡片或其他归属位置，再移除待办。交接时核对相关事项，不要求每次回复都扫描整个项目。

**GLOSSARY：分类维护共同含义**

根据实际内容形成状态与符号、方法与训练、数据与评测、指标与统计、配置与别名等分组。一个概念维护一处定义，别名同行说明，必要时交叉引用。

跨材料复用的术语需要登记；普通目录名、一次性变量无需全部入表。语义变化说明适用范围，保留理解历史材料所需的映射。

用户汇报和交接首次出现术语时仍解释含义。应先说“同时去掉两个组件的对照”，再提供实现标识，不能让读者依赖内部代号理解问题。

**JOURNAL：解释重要历史**

首次需要记录重要事件时，先使用单份 `.agent/JOURNAL.md`，新记录在前。记录发生了什么、原因、影响及证据，不强制等级、行数或阶段字段。

适合记录的重要事件包括路线撤回、重大决定、已确认根因、影响后续工作的失败、重要交接和成果。普通答疑、重复检查、细粒度进度不必记录。

历史事实保留原意；重要纠正追加带日期的说明。阅读确有需要时再归档并留入口，归档不代表完成。

真实案例与格式示例分开。引用历史案例时给出日期或主题及来源路径，行号仅作当次定位辅助，不把不同事件拼成未经核实的因果关系。

**六、公共实现与环境构建**

**公共行为回公共源码**

通用配置装配、参数解析、调度、恢复、评分、统计和报告处理，应有公共实现位置。已有公共职责的缺陷沿实际调用链修正，不能只在当前实验目录补一份，也不必等第二个实验再次踩坑。

实验目录保留科学配置、实验特有分析和采用记录。一次性分析出现真实复用或稳定重复后再抽取，不因“以后可能用”提前建设框架。

应急补丁若暂时落在冻结执行副本中，在本任务内回收到公共来源；确实受阻时登记具体 TODO。运行中的脚本保持稳定，新版本在自然边界采用。

“源码已修复”和“实际任务已采用”分别验证。实际采用利用下一次已授权的真实调用，不为证明采用额外启动科研计算。

**环境入口与版本**

项目用 `environment-<用途>.sh` 提供可重建入口，按真实兼容边界拆环境，不按实验编号复制。

- 说明用途、支持的平台条件、安装位置、使用方式和必要检查。
- 依赖版本只维护一份规格。少量依赖可写在脚本中；较多时使用规格或已有锁文件，由脚本消费。
- 固定所需 Python、包版本、相关 CUDA wheel 变体、源码依赖及模型修订，避免无界升级。
- 按所选用途准备环境和模型，可选能力显式选择；需要分别准备时提供相应模式。
- 成功以相关入口和必要的小检查为准，不只看目录存在；失败如实返回，不擅自降级到其他组合。
- 环境修复同步进入构建入口，不只在某个容器手工安装。
- 不热改正在使用的依赖；不兼容升级在独立环境准备并于自然边界采用。
- 镜像、代理、多机分发和存储位置交给平台适配。

已有合格环境可以直接复用。维护构建入口不等于每次执行前重新构建，独立短核算也不自动启动环境建设。

保留需要追溯的结果时，环境依据必须能还原本次实际采用的内容，并能定位代码、模型与实际配置。已有规格版本或原生运行记录足够时直接引用；若两者都没有，执行入口保存必要的规格与实际依赖记录，放在既有运行产物位置。不能只引用随后会被覆盖的当前文件路径。

当前规格升级不改变旧结果的采用记录；不手抄版本列表，不重复生成已有记录，不默认新增摘要，也不要求先 Git 提交。

**七、验证与案例选择**

新增检查应能回答：要排除什么实际错误、影响哪部分结果，以及什么最小检查能够区分它。

- 实现、输入和协议未变的合格证据直接复用。
- 差异只影响评分，就检查评分，不自动重新训练和生成。
- 发现实现、输入、配置、协议、环境或产物错误时，按实际影响使相关结果失效。
- 路径、版本或容器差异本身不等于错误。
- 当前进程、资源占用、实际写入者和恢复入口属于实时事实，需要现场核实。
- 科学配置一致且合格的正式早期样本可以计入结果，不因曾用于检查就重复计算。
- 估算用于安排和汇报；只有明确生效的硬限制才约束停止或资源使用。

“用几个 case 看看”默认是本次探索。说明来源、选择依据、要回答的问题及结论范围，不自动继承成以后所有实验的固定协议。

已知失败可作为回归案例；正式配对比较在声明范围内固定同一组案例；总体主张需要相应证据。不能看过新方法结果后再挑有利样本，却声称是中立比较。

新问题开始时重新判断旧案例是否适用。影响科学口径的改变与用户讨论，探索性补充与正式比较分开解释。

**八、协作、授权与共享写入**

一个人可以承担所有角色。实际出现独立工作、共享冲突或审阅需求时才拆分：

| 角色 | 责任 |
|---|---|
| 长期任务属主 | 范围、执行、证据、卡片、授权内验收与收口 |
| 根协调者 | 跨任务综合、优先级、共享冲突及用户选择 |
| 公共实现整合者 | 接受公共修改、检查影响、安排实际采用 |
| 有界 worker | 在明确范围内交付产物与证据 |
| 委派方 | 验收有界 worker 的交付，对整体任务负责 |

长期独立任务属主可以在已有授权内接续训练、生成、评分和恢复，不逐阶段等待根批准。一次性 worker 不自行宣布整个任务完成。

新增独立实验、改变冻结科学协议或实质扩大资源范围需要匹配授权；缺口只阻塞依赖部分。额外设备可用不等于获准增加实验。

本 skill 决定何时拆分角色及交接事实放在哪里；长期会话通信和有界委派的执行细则分别交给现有专门 skill，不重复维护。

交接以接收方实际接手并明确接续入口为准。未完成接手时，原属主或协调者继续跟进；交接生效后，原属主停止修改已移交写面。具体通信与回执方式使用现有协调或委派 skill，不新增逐阶段审批。

**共享写入**

同一共享文件存在多个潜在写者时，在开始写入前统一编辑入口或指定本次整合者。潜在写者包括会话、worker、后台任务及可能并发保存该文件的编辑器，不必等现场观察到同时写入。仅打开阅读不计为写者；用户与会话明确顺序交替编辑时，按单写者处理，写前重读即可。

平台可以默认对共享文档使用统一入口；独占写面不因此增加协调步骤。可靠写入应满足：

> 取得有效互斥 → 锁内重读 → 局部合并 → 原子保存 → 回读 → 释放。

原子替换不能单独防止旧快照覆盖。所有并发写者必须使用同一机制；它不能拦截绕过入口的编辑器保存。

无可用工具或不能统一入口时，由主会话或协调者在分派时指定本次整合者，其他参与者返回片段和依据。不设置永久根写入瓶颈。

锁不覆盖计算、网络任务或用户等待。锚点冲突、锁超时只暂停相关写入，不自动覆盖或夺锁。遗留锁由属主核实后处理，不能仅凭年龄或另一宿主的同号 PID 判断可回收。

**skill 定义保证、触发条件和失败交接；平台提供可替换的默认实现。** 具体文件名、目录和锁原语不固化为通用 skill 的前提。

**十、实际使用与验收**

正常流程从一个问题开始：复用现有环境与公共入口，建立必要的目的卡，完成真实比较，保存原生证据，在卡内给出主要结果和判断。需要后续分析时进 TODO；形成重要决定才记 JOURNAL。

异常流程中，先核实际执行与有效产物。例如生成已完成、后处理失败，恢复后处理即可；路径别名修正后证据仍有效，不重新生成全部样本。修复若属于公共行为，应回公共来源，实验只记录采用。

以 Multi-turn 的真实经验检验设计：

| 案例 | 可观察的通过条件 |
|---|---|
| 四臂消融及结果订正 | 一个研究目的一张卡；主表追到同一汇总，参数和逐格证据可查，订正传给实际采用方 |
| 早期术语和 TODO 演变 | 有跨材料理解问题才引入术语表；持续动作集中 TODO，不首日强建全套 |
| 并发整表写回丢条目 | 多写者交错修改后，各方条目均保留，不能只看本次保存成功 |
| 独占资源属主接续 | 授权和依赖满足后直接推进，不增加根会话等待 |
| 实验目录中重复脚手架 | 公共修复进入实际调用源，下一次真实消费者能采用 |
| 路径或环境差异 | 先判断影响，不以差异本身触发全量重跑 |
| 小批案例被持续沿用 | 每次说明用途，区分探索、回归与正式比较 |
| 环境重建 | 按用途重建并运行相关入口，能查明历史结果实际采用的环境 |

历史案例支持设计取舍，不代表新版 skill 已通过整体运行验收。
